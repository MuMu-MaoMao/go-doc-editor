# 04 · 代码风格与质量标准

> 本文档定义 go-doc-editor 的 Go 代码风格、前端规范和安全编码标准。
> **日常编码时**请随时参考本文档。

---

## 4.1 Go 代码规范

### 4.1.1 必须遵守的标准

| 要求 | 检查命令 | 说明 |
|------|---------|------|
| `gofmt` 格式化 | `gofmt -d .` | 所有 `.go` 文件必须通过 |
| `go vet` 无错误 | `go vet ./...` | 提交前必须运行，零警告 |
| 导入顺序正确 | 见下方 | 三组：标准库 / 第三方 / 内部 |
| 导出符号有注释 | 手动检查 | 所有导出类型、函数、常量必须有 Godoc |
| 错误不被忽略 | 手动检查 | 绝不使用 `_` 忽略错误 |

**导入顺序规范**：
```go
import (
    // 第一组：标准库
    "fmt"
    "net/http"

    // 第二组：第三方包
    "github.com/golang-jwt/jwt/v5"

    // 第三组：内部包
    "go-doc-editor/internal/config"
)
```

### 4.1.2 命名规范

| 元素 | 规范 | 示例 |
|------|------|------|
| 包名 | 小写、单数 | `service`、`handler`、`config` |
| 导出类型 | PascalCase | `FileService`、`NewFileHandler` |
| 未导出类型 | camelCase | `fileService`、`userStore` |
| 变量/函数 | 驼峰，短名 | `username`、`safePath` |
| 接口 | 方法名 + `er` | `Storage`（有 `Save()`） |
| 常量 | PascalCase | `DefaultPort`、`TokenExpiry` |
| 测试函数 | `TestXxx` | `TestSafeFilePath` |
| 错误变量 | `ErrXxx` | `ErrUserExists`、`ErrUserNotFound` |
| 请求体 | `xxxRequest` | `chatRequest`、`registerRequest` |
| 响应体 | `xxxResponse` | `authResponse` |

### 4.1.3 本项目已有命名约定

参照项目现有代码，保持一致：

| 上下文 | 规范 | 现有示例 |
|--------|------|---------|
| Handler 结构体 | `XxxHandler` | `AuthHandler`, `FileHandler`, `AIHandler` |
| Service 结构体 | `XxxService` | `FileService`, `AIService` |
| 构造函数 | `NewXxx` | `NewFileService`, `NewAuthHandler` |
| handler 目录 | 每个 handler 一个文件 | `auth_handler.go`、`file_handler.go` |

### 4.1.4 错误处理最佳实践

```go
// ✅ 正确：包装错误，添加上下文
if err != nil {
    return fmt.Errorf("读取文件 %s 失败: %w", filename, err)
}

// ❌ 错误：忽略错误
value, _ := someFunc()

// ❌ 错误：没有上下文的错误
return err
```

## 4.2 前端代码规范

### 4.2.1 JavaScript

- 使用 **ES6 模块**（`import`/`export`），参考 `auth.js` 的模式
- 所有 `fetch` 调用通过已重写的 `window.fetch`（自动携带 token 和 401 处理）
- 避免全局变量，使用模块作用域
- 所有 `await` 调用必须用 `try/catch` 包裹

### 4.2.2 CSS

- 使用 CSS 变量管理主题色（参考 `style.css` 的 `var(--border)`）
- 使用 BEM 风格 class 命名：`.ai-chat-panel`、`.ai-chat-header`
- 移动端断点：`680px`

### 4.2.3 HTML

- 使用 `<script type="module">` 加载 JS
- CDN 资源使用**固定版本**和 **SRI 哈希**
- 遵循基础无障碍：`<label>` 关联输入、`alt` 属性

## 4.3 安全编码规范

| 规则 | 本项目要求 |
|------|-----------|
| 路径遍历防护 | 所有文件操作必须通过 `safeFilePath()` 校验 |
| 密码存储 | 仅存储 bcrypt 哈希，永不存明文 |
| JWT 密钥 | 生产环境必须从环境变量或配置文件读取，禁止硬编码 |
| API 密钥 | AI API key 必须保存在后端，前端不可见 |
| XSS 防护 | 用户内容渲染必须使用 DOMPurify |
| SQL 注入 | 若后续迁移数据库，必须使用参数化查询 |
| CORS | 若开放跨域，必须限制白名单域名 |

### 4.3.1 特别提醒：API 密钥安全

本项目当前的 AI API key 通过 `--ai-key` 命令行参数传入，
**绝对不能**将含密钥的代码提交到 Git 仓库。

```bash
# ✅ 正确：运行时不把密钥写死在代码里
go run cmd/server/main.go --ai-key=your-key

# ❌ 禁止：将密钥硬编码到 main.go 后提交
```
