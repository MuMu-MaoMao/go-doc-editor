# 05 · Go 架构规范

> 本文档定义 go-doc-editor 的 Go 代码架构、目录结构和分层依赖规则。
> **新增功能或重构模块时**请参考本文档。

---

## 5.1 目录结构

本项目采用 **Go 标准项目布局**，已固化为以下结构：

```
go-doc-editor/
├── cmd/                       # 入口点（保持极简）
│   └── server/main.go
├── internal/                  # 私有业务逻辑（Go 编译器强制限制外部导入）
│   ├── config/                # 配置加载（命令行参数、环境变量）
│   ├── model/                 # 数据契约（DTO、请求/响应结构体）
│   ├── auth/                  # JWT 认证工具
│   ├── user/                  # 用户存储（JSON + bcrypt）
│   ├── service/               # 核心业务逻辑
│   ├── handler/               # HTTP 适配器
│   └── middleware/            # HTTP 中间件
├── static/                    # 前端静态资源
├── docs/                      # 项目文档与规范
├── go.mod / go.sum
└── Makefile                   # （建议添加）
```

### 各目录职责

| 目录 | 职责 | 现有文件 |
|------|------|---------|
| `cmd/server/` | 程序入口：加载配置、组装各层、注册路由、启动服务 | `main.go` |
| `internal/config/` | 配置管理：定义 Config 结构体，支持命令行参数和环境变量 | `config.go` |
| `internal/model/` | 数据模型：定义统一响应结构和请求结构体 | `file.go` |
| `internal/auth/` | JWT 认证工具：生成和验证令牌 | `jwt.go` |
| `internal/user/` | 用户存储：基于 JSON 文件的用户管理 | `store.go` |
| `internal/service/` | 核心业务逻辑：文件 CRUD、路径安全校验、AI API 调用 | `file_service.go`, `ai_service.go` |
| `internal/handler/` | HTTP 适配：解析 HTTP 请求、调用 Service、编码响应 | `file_handler.go`, `auth_handler.go`, `ai_handler.go` |
| `internal/middleware/` | HTTP 中间件：JWT 认证拦截 | `auth.go` |
| `static/` | 前端资源：HTML/JS/CSS | `index.html`, `editor.html`, `editor.js`, `ai-chat.js` 等 |

## 5.2 分层依赖规则

```
                    ┌──────────┐
                    │  Handler  │  (HTTP 解析、参数校验、响应编码)
                    └────┬─────┘
                         │ 依赖注入
                    ┌────▼─────┐
                    │  Service  │  (核心业务逻辑、编排)
                    └────┬─────┘
                         │
              ┌──────────┼──────────┐
              ▼          ▼          ▼
         ┌────────┐ ┌────────┐ ┌──────────┐
         │ Model  │ │  Auth   │ │   外部    │  (文件系统 / AI API)
         │ (DTO)  │ │ (JWT)  │ │  User    │
         └────────┘ └────────┘ └──────────┘
```

### 依赖规则矩阵

| 层 | 可以依赖 | 不可以依赖 |
|----|---------|-----------|
| **Handler** | Service、Model、Middleware | 直接操作文件系统、直接调用外部 API |
| **Service** | Model、Auth、外部资源 | 直接处理 HTTP 请求/响应、操作 `http.ResponseWriter` |
| **Middleware** | Auth、标准库 | 依赖 Handler 或 Service |
| **Model/Config** | 仅标准库 | 不能依赖项目内其他包 |

## 5.3 数据流模式

### 普通接口

```
请求 → Handler.ParseRequest()
         → Handler.Validate()       // 参数校验
         → Service.BusinessLogic()  // 业务处理
         → Handler.WriteResponse()  // 编码响应
```

### AI 流式接口（特殊模式）

```
请求 → Handler.ParseJSON()
         → Service.ChatStream(... callback)
              → 外部 API (SSE)
              → callback(delta)      // 逐块回调
         → Handler.Flusher.Write()   // SSE 转发
```

## 5.4 新增功能的规范流程

以添加"文件重命名"功能为例：

| 步骤 | 文件 | 内容 |
|------|------|------|
| 1. Model（如需新结构） | `internal/model/` | 新增重命名请求体 |
| 2. Service | `internal/service/file_service.go` | 新增 `RenameFile()` 方法 |
| 3. Handler | `internal/handler/file_handler.go` | 新增路由处理函数 |
| 4. Middleware（如需新拦截） | `internal/middleware/` | — |
| 5. 路由注册 | `cmd/server/main.go` | 注册新端点 |
| 6. 前端 | `static/editor.js` / `editor.html` | 新 UI 交互 |
| 7. 文档 | `readme.md` | 更新 API 接口列表 |
| 8. 测试 | `internal/service/` | 新增单元测试 |

## 5.5 接口定义原则

- **接口属于消费者**，放在使用它的一方（如 `service` 包），而非实现方
- 保持接口**小**（1-3 个方法）

```go
// ✅ 好的接口：小、聚焦
type FileStorage interface {
    Save(name string, content []byte) error
    Read(name string) ([]byte, error)
    Delete(name string) error
}

// ❌ 不好的接口：太大、通用
type Storage interface {
    Save(name string, content []byte) error
    Read(name string) ([]byte, error)
    Delete(name string) error
    List() ([]string, error)
    Move(old, new string) error
    Copy(src, dst string) error
    Exists(name string) bool
}
```

## 5.6 依赖注入模式

本项目使用**构造函数注入**，所有依赖通过 `NewXxx` 函数传入：

```go
// main.go 中组装各层
fileService := service.NewFileService(cfg.StorageDir)
aiService := service.NewAIService(*aiKey)

authHandler := handler.NewAuthHandler(userStore)
fileHandler := handler.NewFileHandler(fileService)
aiHandler := handler.NewAIHandler(aiService)
```

禁止使用：
- 全局变量（`var` 直接声明跨包共享状态）
- `init()` 函数初始化依赖
- 服务定位器模式
