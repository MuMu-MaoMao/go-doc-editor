# 06 · 文档标准

> 本文档定义 go-doc-editor 的文档体系，包括 ADR、代码注释和 README 规范。
> **做架构决策、写 API 文档或代码注释时**请参考本文档。

---

## 6.1 文档体系结构

```
docs/                         # 项目规范与决策文档
├── INDEX.md                  # 规范索引
├── 01-总体原则.md              # （规范文档）
├── ...                       # （其余规范文档）
├── adr/                      # 架构决策记录
│   ├── ADR-001-use-jwt-auth.md
│   └── ADR-002-deepseek-proxy.md

readme.md                     # 项目技术概览（API、架构、运行方式）
```

## 6.2 架构决策记录（ADR）

### 2.1 何时必须写 ADR

当变更涉及以下场景之一时，必须在 `docs/adr/` 下创建 ADR：

- 引入新的**外部依赖**
- 新增**外部 API 集成**（如更换 AI 模型提供商）
- 项目**架构调整**（如从 JSON 文件迁移到数据库）
- **安全模型**重大变更
- 引入新的设计模式或开发框架

### 2.2 ADR 模板

```markdown
# ADR-NNN: <标题>

- **状态**: [Proposed | Accepted | Deprecated | Superseded]
- **提出日期**: YYYY-MM-DD
- **提出人**: <姓名>

## 上下文

描述问题的背景、驱动力和约束条件。

## 考虑的方案

### 方案 A：<方案名称>
- 优点：...
- 缺点：...
- 成本：...

### 方案 B：<方案名称>
- 优点：...
- 缺点：...
- 成本：...

## 决策

选中方案 A，理由：...

## 影响

### 正面影响
- ...

### 负面影响
- ...

## 关联
- 关联 ADR：ADR-00X
- 关联 Issue：#NN
```

### 2.3 命名和编号

- 编号从 `001` 开始顺序递增
- 文件名格式：`ADR-NNN-<简短描述>.md`
  - `ADR-001-use-jwt-auth.md`
  - `ADR-002-deepseek-proxy.md`
- 状态只使用：`Proposed` → `Accepted` → `Deprecated` → `Superseded`

## 6.3 Go 代码注释规范

### 3.1 包注释

每个包需要一个包级注释，放在 `doc.go` 或包内第一个文件的开头：

```go
// Package service 实现核心业务逻辑层。
// 所有文件操作都基于用户隔离的目录结构，并通过 safeFilePath
// 方法防止目录遍历攻击。
package service
```

### 3.2 导出符号注释

所有导出的类型、函数、常量必须要有注释：

```go
// FileService 提供基于用户隔离的文件 CRUD 操作。
// 每个用户的文件存储在 {baseDir}/{username}/ 下。
type FileService struct {
    baseDir string
}

// NewFileService 创建 FileService 实例。
// baseDir 是文档存储的根目录。
func NewFileService(baseDir string) *FileService {
    return &FileService{baseDir: baseDir}
}
```

### 3.3 注释风格

- 注释以**符号名称开头**（如 `FileService`、`NewFileService`）
- 注释是**完整句子**，以句号结尾
- 注释说明"**做什么**"而非"**怎么做**"
- 对复杂逻辑，在函数**内部**加行内注释说明"为什么这么做"

## 6.4 README 维护规范

`readme.md` 应始终包含以下内容，修改功能时同步更新：

| 章节 | 变更时需更新 |
|------|------------|
| 项目描述 | 项目定位改变时 |
| 架构概览 | 新增/删除模块时 |
| 目录结构与文件职责 | 增删文件时 |
| API 接口文档 | 新增/修改/删除 API 端点时 |
| 依赖列表 | 增加/更新依赖时 |

## 6.5 提交与文档的关联

- 如果提交包含架构变更，在 body 中引用 ADR（`See ADR-002`）
- 如果提交修复了 issue，使用 `Fixes #N`
- **纯文档变更**使用 `docs:` 类型单独提交，不与代码变更混合
