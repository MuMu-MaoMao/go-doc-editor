# 09 · 发布与版本管理

> 本文档定义 go-doc-editor 的版本号方案、发布流程和 Changelog 规范。
> **发布新版本时**请按本文档步骤操作。

---

## 9.1 版本号方案

采用 **语义化版本 SemVer 2.0**：

```
MAJOR.MINOR.PATCH

MAJOR（主版本）：不兼容的 API 变更
  - 路由路径变更（如 /api/file → /api/documents）
  - 请求/响应结构不兼容变更
  - 移除已有功能

MINOR（次版本）：向后兼容的新功能
  - 新增 API 端点
  - 新增 Service 方法
  - 新前端页面或功能

PATCH（修订版本）：向后兼容的 Bug 修复
  - 安全修复
  - 错误处理改进
  - 文档修正
  - 性能优化（不改变 API）
```

**当前版本**：在 `go.mod` 中通过 Git tag 管理，初始为 `v0.1.0`。

## 9.2 发布流程

```bash
# 1. 确认 main 分支通过所有测试
git checkout main
git pull origin main
go test ./... -race

# 2. 创建版本 Tag
git tag v0.2.0

# 3. 推送 Tag
git push origin v0.2.0

# 4. （可选）构建二进制文件
go build -o bin/go-doc-editor cmd/server/main.go

# 5. 在 GitHub 上创建 Release
#    - 填写版本号
#    - 粘贴 Changelog 内容
#    - 上传构建产物（可选）
```

### 版本号决定规则

查看自上一版本以来的提交信息：

```
feat: → MINOR 加 1，PATCH 归零
fix:  → PATCH 加 1
docs/chore/style/test: → 不触发版本变更
BREAKING CHANGE: → MAJOR 加 1
```

## 9.3 Changelog 规范

`CHANGELOG.md` 文件记录每个版本的变更：

```markdown
# Changelog

## [v0.2.0] - 2026-06-06

### 新增
- feat(handler): add file rename API (#42)
- feat(static): add file search bar (#39)

### 修复
- fix(service): correct path traversal check on Windows (#38)
- fix(auth): handle expired token gracefully (#36)

### 重构
- refactor(ai): extract SSE writer to separate helper (#35)

### 杂项
- chore(deps): bump golang-jwt to v5.2.2 (#33)
```

### 格式规范

- 版本号按**时间倒序**排列
- 每种变更类型使用小标题 `### 新增` / `### 修复` / `### 重构` / `### 杂项`
- 每条记录包含 PR/Issue 编号的引用
- 新版本发布时自动追加

## 9.4 预发布版本

对于需要测试但未正式发布的版本，使用预发布后缀：

```
v0.2.0-alpha.1    # 内部测试
v0.2.0-beta.1     # 公开测试
v0.2.0-rc.1       # 发布候选
```

预发布版本不会触发自动部署。
