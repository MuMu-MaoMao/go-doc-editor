# 10 · AI 集成开发规范

> 本文档定义 go-doc-editor 中 AI 相关功能的开发规范。
> **修改 AI 功能、更换模型或集成新 AI 能力时**请参考本文档。

---

## 10.1 通用规则

1. **AI 密钥只能存在于后端**，通过命令行参数 `--ai-key` 或环境变量注入
2. **AI 请求必须走后端代理**：`前端 → POST /api/ai/chat → 后端 Go → DeepSeek API`
3. **前端绝对不能直接调用外部 AI API**（密钥会暴露）
4. **所有 AI 接口受 JWT 保护**，需要有效的 Bearer Token

## 10.2 当前实现架构

```
                   ┌──────────────────────┐
                   │   前端 editor.html    │
                   │   (ai-chat.js)        │
                   └──────┬───────────────┘
                          │ POST /api/ai/chat
                          │ Authorization: Bearer <token>
                          ▼
┌──────────────────────────────────────────────┐
│          后端 Go (cmd/server/main.go)          │
│                                              │
│  → middleware/auth.go (JWT 验证)               │
│  → handler/ai_handler.go (SSE 响应适配)        │
│  → service/ai_service.go (调用 DeepSeek API)   │
│      → POST api.deepseek.com (Stream)         │
│      ← SSE 逐块转发 → 前端                     │
└──────────────────────────────────────────────┘
```

## 10.3 AI Service 层设计模式

AI 服务遵循**回调模式**实现流式响应：

```go
// StreamCallback 是 SSE 逐块转发的回调函数
type StreamCallback func(delta string)

// ChatStream 调用外部 AI API 并以流式返回结果
// messages: 对话历史（含 system/user/assistant）
// onChunk: 每收到一个内容片段时调用
// 返回值: 完整响应内容（用于记录历史）
func (s *AIService) ChatStream(messages []Message, onChunk StreamCallback) (string, error) {
    // 1. 构建请求体（含 model、messages、stream=true）
    // 2. POST 外部 AI API
    // 3. 逐行读取 SSE 响应
    // 4. 解析 JSON，提取 delta，通过 onChunk 转发
    // 5. 返回完整拼接内容
}
```

### 新增 AI 功能开发流程

| 步骤 | 涉及文件 | 说明 |
|------|---------|------|
| 1. 后端业务逻辑 | `internal/service/ai_service.go` | 新增或修改 AI 调用方法 |
| 2. HTTP 适配 | `internal/handler/ai_handler.go` | 新增或修改端点处理函数 |
| 3. 路由注册 | `cmd/server/main.go` | 注册新路由（受 JWT 保护） |
| 4. 前端交互 | `static/ai-chat.js` / `editor.html` | 实现 UI 交互 |
| 5. ADR（如换模型） | `docs/adr/` | 记录架构决策 |

## 10.4 SSE 协议规范

前后端 SSE 通信的格式必须保持一致：

### 发送格式（后端 → 前端）

```
data: {"type":"start"}              // 开始标记
data: {"type":"chunk","delta":"回复片段"}  // 内容片段
data: {"type":"done","content":"完整回复"} // 完成标记
data: {"type":"error","message":"错误描述"} // 错误通知
```

### 接收格式（前端）

前端通过 `ReadableStream` 逐行解析：

```javascript
const reader = response.body.getReader();
const decoder = new TextDecoder();
let buffer = '';

while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split('\n');
    buffer = lines.pop() || '';

    for (const line of lines) {
        if (line.startsWith('data: ')) {
            const data = JSON.parse(line.slice(6));
            // 根据 data.type 处理 start/chunk/done/error
        }
    }
}
```

## 10.5 更换 AI 模型的注意事项

如需更换模型（如从 DeepSeek 切换到其他）：

| 事项 | 说明 |
|------|------|
| API URL | 修改 `service/ai_service.go` 中的 `deepseekAPIURL` |
| 模型名称 | 修改请求体中的 `Model` 字段 |
| 认证方式 | 确认 API key 的 Header 格式（`Authorization: Bearer` 或其他） |
| 响应格式 | 不同模型的 SSE 数据格式可能不同，需调整解析逻辑 |
| 参数适配 | Temperature、MaxTokens 等参数可能需要调优 |
| ADR 记录 | 必须创建 ADR 记录模型更换的原因和影响 |

## 10.6 AI 相关安全规则

- API key **禁止提交到 Git**。使用 `--ai-key` 参数传入，或将密钥文件添加到 `.gitignore`
- 前端发送给 AI 的内容已经是用户自己的文档，保障了数据隐私
- 对话历史前端维护，服务器不做持久化
