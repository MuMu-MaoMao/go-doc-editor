## 11.1 开发环境搭建

```bash
# 1. 克隆项目
cd go-doc-editor

# 2. 安装 Go 依赖
go mod tidy

# 3. 运行服务
go run cmd/server/main.go --ai-key=your-api-key-here

# 4. 指定端口和存储目录
go run cmd/server/main.go \
    --ai-key=your-key \
    -port :8080 \
    -storage "C:\my_docs"

# 5. 编译为可执行文件
go build -o bin/go-doc-editor.exe cmd/server/main.go
```

## 11.3 Makefile 建议

在项目根目录创建 `Makefile`，集中管理常用命令：

```makefile
.PHONY: run build test lint vet clean

# 运行
run:
	go run cmd/server/main.go --ai-key=${AI_KEY}

# 编译
build:
	go build -o bin/go-doc-editor.exe cmd/server/main.go

# 测试
test:
	go test ./... -v -race

# 覆盖率
cover:
	go test ./... -coverprofile=coverage.out
	go tool cover -html=coverage.out

# Lint
lint:
	go vet ./...

# 格式化
fmt:
	gofmt -w .

# 清理
clean:
	rm -rf bin/ coverage.out
```

## 11.4 .gitignore 建议

添加到项目根目录的 `.gitignore`：

```
# 可执行文件
bin/
*.exe

# 用户数据
data/

# 编辑器
.vscode/
.idea/

# 系统
.DS_Store
Thumbs.db

# 配置文件（含密钥）
.env
*.local.*
```

> **注意**：当前项目根目录还没有 `.gitignore` 文件。
> 建议及时创建，防止意外提交密钥和系统文件。

## 11.5 常见反模式

| ❌ 反模式 | ✅ 正确做法 | 本项目情况 |
|-----------|-----------|-----------|
| 在 Handler 中直接操作文件系统 | 调用 Service 层 | ✅ 已是正确模式 |
| 硬编码配置值（端口、路径） | 通过 Config 结构体管理 | ✅ `config.go` 已实现 |
| 使用 `pkg/` 当杂物筐 | 只在需要对外发布时用 | ✅ 本项目无 `pkg/` |
| 忽略错误（`_`） | 处理或包装错误 | ⚠️ 部分代码需改进 |
| 在前端存储 API Key | 通过后端代理调用 | ✅ 已是正确模式 |
| 一个 PR 做多件事 | 一个 PR 只做一个逻辑变更 | — |
| 使用 `util/`、`common/`、`helper/` | 语义化包名 | ✅ 当前结构合理 |
| `init()` 初始化复杂依赖 | 构造函数显式注入 | ✅ 当前使用 `NewXxx` 模式 |

## 11.6 常用命令速查

```bash
# 开发
go run cmd/server/main.go --ai-key=sk-xxx   # 启动服务
go mod tidy                                    # 同步依赖

# 测试
go test ./... -v                               # 详细测试输出
go test ./... -race                            # 竞态检测
go test ./... -cover                           # 覆盖率
go test ./internal/service/ -run TestSafeFilePath  # 单个测试

# 代码质量
go vet ./...                                   # 静态分析
gofmt -l .                                     # 检查格式
gofmt -w .                                     # 自动格式化

# Git
git commit -m "feat(handler): add ..."          # 规范提交
git tag v0.1.0                                  # 打版本标记
```
