# ADR-001: 用户认证架构决策

- **状态**: Accepted
- **提出日期**: 2026-05-01
- **提出人**: 项目初始团队

## 上下文

项目最初没有用户系统，所有文档存储在共享文件目录中，
任何人都可以访问任何文件。随着项目发展，需要引入用户认证以满足：

- 用户文档隔离（每个用户只能访问自己的文件）
- 密码安全存储
- 无状态认证（便于后续水平扩展）

## 考虑的方案

### 方案 A：Session-Cookie 认证
- 优点：实现简单，服务端完全控制会话
- 缺点：需要服务端存储 session，不利于扩展
- 成本：需要引入 session 存储（内存/Redis）

### 方案 B：JWT 令牌认证（选中）
- 优点：无状态，不需要服务端保存会话；天然适合前后端分离
- 缺点：令牌一旦签发无法主动吊销（直到过期）
- 成本：添加 `github.com/golang-jwt/jwt/v5` 依赖

### 方案 C：OAuth 2.0 第三方登录
- 优点：用户无需注册，降低使用门槛
- 缺点：需要第三方服务依赖；本地文档编辑器场景不适用
- 成本：需要引入 OAuth 流程，复杂度高

## 决策

选中**方案 B（JWT 令牌认证）**，理由：

1. 项目为本地文档编辑器，前后端分离
2. 无状态认证符合分层架构设计
3. 实现成本低，仅需添加一个依赖包

## 影响

### 正面影响
- 认证无状态，认证逻辑集中在 `internal/auth/` 和 `internal/middleware/` 中
- 用户文档天然隔离（存储路径包含用户名）
- 前端通过 `localStorage` 存储 token，实现简单

### 负面影响
- JWT 密钥硬编码在 `internal/auth/jwt.go` 中，生产环境需改为配置
- 令牌 24 小时过期，暂无刷新令牌机制

## 安全考量
- 密码使用 `bcrypt` 加密存储
- 路径遍历防护通过 `safeFilePath()` 方法实现
- 前端 fetch 自动拦截 401 跳转登录
