# 迭代记录 2：拉伸体验修复

- **日期**: 2026-06-06
- **当前阶段**: 迭代修复 ✅

---

## 问题描述

用户测试反馈：AI 对话框的拉伸体验不好，鼠标按住边框时偶尔拖不动，
反而变成选中文本。左右下及四角都有这个问题，有时行有时不行。

## 根因分析

原有实现使用**边缘检测**（鼠标距面板边缘 < 8px 判断需要拉伸），存在三个问题：

1. **命中区域不可靠**：数学计算受 DOM 事件冒泡影响，点击传到了子元素（如消息区滚动条）上就不能触发
2. **没有防止文本选中**：mousedown 时没有全局禁止文本选择，浏览器优先选中了文字
3. **事件冲突**：mousemove 的边缘检测与面板内部滚动条等事件冲突

## 修复方案

改用**8 个显式 resize handle 元素**替代边缘检测：

### HTML 变更
- 在 `.ai-chat-panel` 内添加 8 个 `.resize-handle` div（n/s/e/w/ne/nw/se/sw）
- 内容包裹在 `.ai-chat-panel-inner` 中

### CSS 变更
- `.ai-chat-panel` 去掉 `overflow: hidden`（让 handle 可以延伸到边框外）
- 新增 `.ai-chat-panel-inner` 承接 `overflow: hidden`（内容仍被正确裁剪）
- handle 尺寸：边 = 10px 粗、角 = 18x18px
- handle 延伸出面板边缘 5px，确保鼠标能轻松命中
- 每个 handle 直接通过 CSS 设置 `cursor`

### JS 变更
- 移除所有边缘检测函数（`getResizeDirection`、`getResizeCursor` 等）
- handle 的 `data-dir` 属性直接告诉 JS 拉伸方向
- 拖拽/拉伸时设置 `document.body.style.userSelect = 'none'`，**全局禁止选中文本**
- 结束时恢复 `document.body.style.userSelect = ''`

## 优势

| 对比 | 旧方案（边缘检测） | 新方案（显式 handle） |
|------|------------------|-------------------|
| 命中面积 | 仅 8px 边缘，且受事件冒泡影响 | 10px 粗 handle，完全独立于内容 |
| 光标反馈 | 靠 JS 计算 | CSS 直接定义，实时、可靠 |
| 选中文本 | 会选中 | `user-select: none` 全局禁止 |
| 四角拉伸 | 需要方向判断逻辑 | 角 handle 18x18px，超大命中区 |
