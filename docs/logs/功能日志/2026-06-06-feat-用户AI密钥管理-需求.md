## 功能描述

为用户提供自主管理 AI-Key 的能力，不再依赖命令行参数。

### 三大改造

1. **数据库重构**：新建 `ai_keys` 表，每个用户可绑定多个 API Key
2. **用户主页改造**：新增 API-Key 管理界面，用户可上传/选择 Key、URL、模型
3. **AI 调用重构**：AI 对话使用用户当前选择的 Key + 模型，不再依赖全局 `--ai-key`

## 数据库设计

```sql
CREATE TABLE ai_keys (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    username    VARCHAR(255) NOT NULL,
    key_name    VARCHAR(100) NOT NULL,      -- 用户自定义名称，如 "我的 DeepSeek"
    api_key     VARCHAR(255) NOT NULL,       -- 加密后的 API Key
    api_url     VARCHAR(255) NOT NULL DEFAULT 'https://api.deepseek.com/v1/chat/completions',
    model       VARCHAR(100) NOT NULL,       -- 模型名，如 deepseek-chat / deepseek-reasoner
    is_active   TINYINT(1) NOT NULL DEFAULT 0, -- 当前是否激活使用
    created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_ai_keys_username (username)
);
```

## 用户页面新需求

- 在 profile 页面新增"AI 配置"区域
- 显示已添加的 Key 列表
- 可新增 Key（名称 + API-Key + URL + 模型选择）
- 模型选项：DeepSeek-Flash (deepseek-chat)、DeepSeek-Pro (deepseek-reasoner)
- 可激活/删除 Key
- 每次只能激活一个 Key

## AI 调用重构

- `ChatStream` 改为接收 `apiKey`、`apiURL`、`model` 参数（从数据库读取用户激活的配置）
- 如果用户没有配置 Key，则回退使用全局 `--ai-key`

## 初步接受标准

- [ ] 用户可在 profile 页面添加 AI-Key
- [ ] 支持 DeepSeek-Flash 和 DeepSeek-Pro 两个模型
- [ ] 用户可切换激活不同的 Key
- [ ] AI 对话时自动使用用户激活的 Key + 模型
- [ ] 未配置 Key 的用户仍可使用全局 `--ai-key`
- [ ] config.json 中的 `ai_key` 作为全局保底值
