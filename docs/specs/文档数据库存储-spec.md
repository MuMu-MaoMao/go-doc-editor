# 文档数据库存储 — 规格说明

> **功能名称**: 文档数据库存储
> **关联需求 Log**: `docs/logs/功能日志/2026-06-06-feat-文档数据库存储-需求.md`

---

## 1. 目标

将文档存储从**文件系统**迁移到 **MySQL 数据库**，以解决数据分散、元数据缺失、无法利用数据库查询能力等问题。本次变更对前端完全透明，API 接口的请求/响应格式保持不变。

## 2. 项目结构影响

### 2.1 新增文件

| 文件 | 说明 |
|------|------|
| `internal/docstore/doc_store.go` | 文档数据库存储模块，封装所有文档 CRUD 的 SQL 操作 |

**为什么选择新增 `docstore` 包而非放在已有包中？**
- `internal/service/file_service.go` 是业务逻辑层，将存储细节抽象到 `docstore` 包可使关注点分离
- `db` 包只负责连接管理和建表，不应包含业务数据操作
- 未来若需要切换存储方式（如迁移到其他数据库），只需替换 `docstore` 实现

### 2.2 修改文件

| 文件 | 变更说明 |
|------|---------|
| `internal/db/mysql.go` | 新增 `documents` 表的 `CREATE TABLE` 语句 |
| `internal/service/file_service.go` | 从文件系统操作改为调用 `docstore` 的数据库操作；构造函数改为接收 `*docstore.Store` |
| `internal/model/file.go` | 新增 `Document` 模型结构体（用于可能的扩展查询），`Response` 结构不变 |
| `cmd/server/main.go` | 创建 `docstore.Store` 并注入到 `FileService`；`storage` 目录检查改为可选 |
| `internal/config/config.go` | `StorageDir` 改为可选字段（可保留用于未来其他用途，但不再是文档存储的必须项） |
| `readme.md` | 更新目录结构章节、API 说明（如有变更）、数据库章节增加 documents 表描述 |
| `docs/` | 新增 `ADR-005` |

### 2.3 不变文件

前端的 HTML/JS/CSS（`static/` 目录）完全不变。

## 3. 代码风格

- 遵循现有项目规范：Go 标准布局、Conventional Commits
- 所有导出符号（类型、函数）必须写注释
- SQL 全部使用参数化查询（`?` 占位符），不使用任何字符串拼接
- 事务使用：文档保存操作（INSERT/UPDATE）应使用事务确保一致性
- 错误处理风格与现有 `user/store.go` 保持一致：错误类型用哨兵错误（sentinel error）

## 5. 边界条件

### 5.1 文档内容长度

| 条件 | 预期行为 |
|------|---------|
| 空内容（""） | 正常保存，返回成功 |
| 超长内容（> 64KB） | 使用 LONGTEXT 类型，支持最大 4GB |
| UTF-8 中文/特殊字符 | 表字符集 utf8mb4，正常存储 |

### 5.2 文件名

| 条件 | 预期行为 |
|------|---------|
| 空文件名 | 返回错误（已有校验，保持不变） |
| 文件名包含特殊字符 | 数据库中直接存储，无需文件系统路径限制 |
| 文件名超长 | MySQL VARCHAR(255) 限制，超长返回错误 |
| 包含中英文的文件名 | 正常存储 |

### 5.3 用户隔离

| 条件 | 预期行为 |
|------|---------|
| 用户 A 查询文件列表 | 只显示用户 A 的文件 |
| 用户 B 尝试读取用户 A 的文件 | 通过用户名参数过滤，无法跨用户访问 |

### 5.4 并发/一致性

| 条件 | 预期行为 |
|------|---------|
| 同时保存同一文件 | 最后写入的覆盖（无锁，与文件系统行为一致） |
| 删除不存在的文件 | 返回"文件不存在"错误（与文件系统行为一致） |
| 读取不存在的文件 | 返回 404 错误 |

### 5.5 移除了什么

| 原文件系统行为 | 新行为 |
|---------------|-------|
| `C:\doxreader/{username}/` 目录 | 不再需要，storage 配置变为可选 |
| 路径遍历安全检查（`safeFilePath`）| 不再需要，数据库查询天然防止路径穿越 |
| `EnsureUserDir` / 目录创建 | 不再需要 |

## 6. 成功标准

- [ ] `documents` 表结构已定义，包含 id / username / filename / content / created_at / updated_at，并建有合适的索引
- [ ] 列出文件（`GET /api/files`）返回对应用户的文档名列表，JSON 格式与原来一致：`{"success":true,"files":["a.md","b.md"]}`
- [ ] 读取文件（`GET /api/file/{name}`）返回文档内容，JSON 格式与原来一致：`{"success":true,"content":"..."}`
- [ ] 保存文件（`POST /api/file/{name}`）将内容写入数据库，返回 `{"success":true,"message":"文件保存成功"}`
- [ ] 删除文件（`DELETE /api/file/{name}`）从数据库删除文档，返回 `{"success":true,"message":"文件删除成功"}`
- [ ] 新建文件后立即读取，内容一致
- [ ] 重复保存同一文件，取最新内容
- [ ] 用户 A 看不到用户 B 的文件
- [ ] 项目不依赖 `C:\doxreader` 目录即可启动和运行
- [ ] 启动日志无新增错误输出
