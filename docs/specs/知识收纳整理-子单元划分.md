# 知识收纳整理 — 子单元划分

> **关联全景需求**: `docs/specs/知识收纳整理-全景需求.md`
> **关联流程**: 范式 Super（`docs/13-范式Super-特大规模开发流程.md`）

---

## 划分依据

根据功能依赖关系和改动范围，将知识收纳整理系统拆解为 **3 个子单元**：

- **子单元 1**：全局数据库设计（新增表，不动旧表）
- **子单元 2**：三级分类体系前后端实现
- **子单元 3**：关键语句标注与跨文档关联

## 依赖关系图

```
子单元 1: 数据库设计
  │ 定义所有新表结构，但不实现功能
  ▼
子单元 2: 三级分类体系 ──── 范式 A
  │ 依赖子单元 1 的数据表
  ▼
子单元 3: 关键语句标注与关联 ──── 范式 A
  │ 依赖子单元 1 的数据表 + 子单元 2 的分类功能
  ▼
全局回归测试
```

## 子单元清单

| 编号 | 名称 | 范式类型 | 预计工时 | 依赖 | 说明 |
|------|------|---------|---------|------|------|
| 1 | 全局数据库设计 | **范式 B**（轻量） | 0.5h | 无 | documents 加 category_id 字段 + 新建 categories 和 annotations 表 |
| 2 | 三级分类体系 | **范式 A**（完整规格） | 2-3h | 子单元 1 | 分类 CRUD + 前端树形展示 |

## 各子单元范围描述

### 子单元 1：全局数据库设计

**范围**：documents 表加 category_id 字段，新建 categories 和 annotations 表。

**涉及文件**：
- `internal/db/mysql.go` — 新增建表语句 + ALTER TABLE
- `docs/adr/` — 如涉及重大决策可写 ADR

**产出**：建表 SQL + 表结构说明文档

### 子单元 2：三级分类体系

**范围**：分类 CRUD + 文档挂载到分类 + 前端侧边栏树形展示。

**涉及层级**：数据库 + 后端（handler/service/docstore）+ 前端（侧边栏）

**后端接口**：
- `POST /api/categories` — 创建分类
- `GET /api/categories` — 获取分类树
- `PUT /api/categories/:id` — 修改分类名称
- `DELETE /api/categories/:id` — 删除分类
- `PUT /api/file/:filename/category` — 设置文档的分类
- `GET /api/files?category=:id` — 按分类查询文档

**前端变更**：
- 编辑器侧边栏新增分类树
- 编辑器顶部/侧边新增分类选择器

### 子单元 3：关键语句标注与跨文档关联

**范围**：选中文字 → 添加标注 → 关联到其他文档 → 被关联方看到引用提示。

**后端接口**：
- `POST /api/annotations` — 创建标注（选中文本 + 关联文档 + 评语）
- `GET /api/file/:filename/annotations` — 获取某文档的所有标注
- `DELETE /api/annotations/:id` — 删除标注
- `GET /api/file/:filename/references` — 获取引用此文档的其他标注

**前端变更**：
- 编辑器选中文字后弹出标注按钮
- 标注面板展示当前文档的标注
- 被引用提示条

## 排期总览

```
Day 1:
  [上午] 子单元 1: 数据库设计（0.5h）
  [下午] 子单元 2: 三级分类体系（范式 A）

Day 2:
  [上午] 子单元 2: 三级分类体系（续）+ 验收
  [下午] 子单元 3: 关键语句标注与关联（范式 A）

Day 3:
  [上午] 子单元 3（续）+ 验收
  [下午] 全局回归测试
```

## 风险点

| 风险 | 缓解措施 |
|------|---------|
| 子单元 2 和 3 工作量超预期 | 范式 A 内部可灵活调整 Task 数量，按需增减 |
| 前端树形展示复杂 | 先实现最基本的树（<ul><li>），不追求交互完美 |
| 标注选区在 Markdown 中可能不准 | 先选中纯文本区域，不涉及富文本渲染偏移 |
